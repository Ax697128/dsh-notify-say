### 1. HTTP 接口安全边界（✅ 主体已完成，余项见下）

**2026-10-18 实测结论**：宿主 `/api` 网关有鉴权（无凭据 401），
但插件 `webServer.register()` 的路由**不在保护范围** ——
不带凭据 POST `config/set` 返回 200 且真的改了配置。

已完成（v0.4.24）：
- [x] 查清监听地址（webServer 默认 `127.0.0.1`）与鉴权边界
- [x] `readJsonBody()` 加 64 KB 累计上限（413 区分于 400）
- [x] `preview` / `selftest` 3 秒最小间隔限流（429 + retry-after）
- [x] 本地来源防护：Origin/Referer 必须本机回环、拒绝 cross-site、
      写操作强制 JSON（堵死跨站表单提交）

**剩余待做**：
- [ ] `consume` 仍用 GET 清状态（语义上应 POST）—— 已加来源防护，
      但语义仍不理想；改动需同步 client.js 与测试
- [ ] `selftest` / `preview` 仍是 GET 触发副作用 —— 同上
- [ ] 加「导出诊断」时的脱敏（见第 5 项）

**仍然存在的局限（如实记录）**：
- 不防本机进程。本机进程伪造 Origin 很容易，但它在 Windows 上本来

### 7. ✅ 自热重载移出生产路径（已完成 v0.4.57）

**原计划**：生产版不给普通开关、开发版保留、待宿主接口稳定后再正式支持。

**实际做法（比计划更彻底）**：把「自动监听 → 自动重载」整个删掉，
改成**用户点一次按钮、尝试一次**。

**触发原因**：2026-10-18 宿主崩溃。崩溃日志两条硬证据 ——
  · 45 条「热重载失败：fingerprint unchanged（旧代码仍在运行）」
    （那天为调 UI 改了 40 多次文件，每次保存都触发一次注定失败的尝试）
  · 同一时刻反复「Session reference "..." is released」
    （每次重载都 dispose 实例，而 dispose 会释放渲染进程仍在用的会话引用）

**新设计**：
- [x] 删除 watcher（`watchPackage` 彻底移除），没有任何自动触发路径
- [x] `POST /reload` 一次性入口，只接受 POST、算写操作、5 秒限流
- [x] 决策抽成纯函数 `planReload()`：
      代码没变 → noop（一次 dispose 都不做）；路径变了 → 拒绝并提示重启；
      确实变了 → 尝试一次，失败**不重试**
- [x] 成功/失败都写进 `notify.log`（`[reload] OK by-user` / `[reload] FAILED`）
- [x] GUI 只有按钮，没有开关；注明「不会自动重复」与「升级后必须重启」

**仍未解决（如实记录）**：
- 自重载在宿主里**经常失败**（Node 模块缓存无法可靠穿透传递依赖）。
  noop 判断能挡掉"没必要"的尝试，但挡不掉"代码变了却重载不上去"。
  所以它仍是实验性能力，界面明确说"失败请重启"。

> **验证判据本身的三条通则**（每条都是真栽过才写下的）：
> ① **一个 code 覆盖相反行为时，只断言 code 等于没断言** —— 必须连理由文字一起钉，
>    而且要**双向**钉：既断言「必须说什么」，也断言「不许说什么」。
>    第六轮的两条 P2 全都是「只钉了一半」：② 钉了 code 没钉理由，③b 钉了但用了或关系。

>    这类"判据被兜底顶替"只能靠逐条钉理由或逐条删产出点扫描才能发现。
> ③ **「或」关系的断言等于没断言**：`/A|B/` 只要有一个词残留就能蒙过去。
>    要拆成互斥的独立断言，并补 `doesNotMatch` 挡住相反说法。
