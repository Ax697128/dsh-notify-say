### 1.3 关键缺口：**没有生成记录**

这是本方案最实质的约束。当前**没有**保存：

- 每个 wav 的原始台词文本
- 使用的 `style_id`
- 语速/音高/抑扬参数
- VOICEVOX 引擎版本

**影响**：无法复现生成、无法证明某文件对应该角色。外部审阅建议的 `AUDIO_MANIFEST.csv`（含 SHA-256、生成文本、许可 URL）目前**无法完整填写**。

**可补救程度**：部分。VOICEVOX 引擎仍在本机（`E:\Tools\VOICEVOX`，2.3 GB），但仅凭音频无法反推原始参数。

### 1.4 已查证的条款要点

| 来源 | 结论 |
|---|---|
| [VOICEVOX 软件条款](https://voicevox.hiroshiba.jp/term/) | 商用/非商用皆可；软件本身禁止再分发；需署名 |
| [ずんずんプロジェクト音源规约](https://zunko.jp/con_ongen_kiyaku.html) | 商用/非商用皆可；需署名 `VOICEVOX:ずんだもん` 式；**规定了向"他者"授权时须传递条款义务** |
| [もち子さん 角色规约](https://vtubermochio.wixsite.com/mochizora/) | **禁止无偿配布/有偿贩卖其合成音声制作的音声素材**（已有官方原文支持，见 §1.5） |
| [VOICEVOX vvm README](https://github.com/VOICEVOX/voicevox_vvm/blob/main/README.md) | **ユーレイちゃん**：非商用可（含同人/直播收入），**商用须向 U-Stella 事前确认** |

**关键判读分歧**：

- **甲方观点**：ずんずん条款写了"向他者授权时须传递义务"，说明再分发**是被考虑的、允许的**，只是须附条件。
- **乙方观点**：该条款只规定义务传递，**未明确授予再分发权**；且各角色条款差异大，不能一概而论。

**本方案不预设哪方正确，而是采用"最保守做法可同时满足两方"的路径**（见 §3）。

## 2. 技术约束（已实测，非推测）

| 能力 | 结果 | 影响 |
|---|---|---|
| 宿主 `fetch` 联网 | ✅ 可用（Node 24 内置，实测 HTTP 200） | 可实现下载 |
| `node_modules` 写入 | ❌ 不可写 | 不能把语音包放安装目录 |
| `$DSH_HOME/storages` 写入 | ✅ 可写 | 但那是配置目录，不该放音频 |
| 渲染进程写文件 | ❌ 沙箱内无 fs | 必须由宿主侧写盘 |
| GUI 与宿主通信 | ✅ 已有 HTTP route 机制 | 可加 `/voicepack` 路由 |

### 2.1 体积对比（决定"是否内置合成"）

```
VOICEVOX 完整安装：2,348 MB
本插件发布包：        4.2 MB
```

**结论：绝不内置 VOICEVOX**（体积 550 倍，且条款明确禁止再分发软件本身）。
同理不内置 Piper/Kokoro（需 Python 运行时，把纯 JS 插件变成需装环境的东西）。

## 3. 方案选项（三个，互斥）

### 方案 A：只做下载，不做合成（**推荐**）

```
用户点「下载语音包」→ 从 GitHub Release 取 zip → 解压到
%LOCALAPPDATA%\dsh-notify-say\voice-lines\<音色>\
```

| 维度 | 评价 |
|---|---|
| 用户成本 | 零安装，按需下载 2.8 MB/音色 |
| 我们成本 | 一次性打包上传（我们已有 247 个文件） |
| 合规 | 取决于 §1.2 审核结果；方案本身不改变合规性 |
| 技术难度 | 低（fetch + 解压 + 写盘） |

**这是唯一能在「合规」与「用户体验」间取平衡的方案。**

### 方案 B：用户自装 VOICEVOX，插件调用其 API 生成

```
检测 http://127.0.0.1:50021 → 有则调用合成 → 写盘
```

| 维度 | 评价 |
|---|---|
| 合规 | **零风险**（用户在自己机器上用官方软件生成） |
| 用户成本 | 装 2.3 GB 软件 |
| 技术难度 | 中（需处理 VOICEVOX 未启动、版本差异） |

**可作为 A 的补充路径**，给"愿意装软件换全音色"的用户。

### 方案 C：改用 Kokoro/Piper 等在许可上更明确的开源模型

| 维度 | 评价 |
|---|---|
| 合规 | 可能更清晰，但**需先核实模型卡是否允许分发输出** |
| 音色 | 不如动漫角色有个性，中文支持不如 VOICEVOX |
| 工作量 | 需重新生成全部素材 |

**不推荐作为第一版**，可作为长期备选。

## 4. 拟采纳的路径（A + 分阶段审核）

### 阶段 1：建立审核基础设施（不依赖任何人，可立即做）

1. **移除 `mochiko`**（唯一有明确负面证据的音色）
2. 生成 `AUDIO_MANIFEST.csv`：文件名、SHA-256、音色、池（done/fail/…）、体积、状态
   - 生成文本/参数等字段**留空并标注"未记录"**（诚实优于编造）
3. 写 `THIRD_PARTY_AUDIO.md`（第三方音频声明，非许可证）
4. GUI 加「音源授权」页面，展示当前音色的署名与限制
5. 下载前必须弹确认（显示署名要求 + 禁止用途）

### 阶段 2：逐音色核对官方条款

对 §1.2 中 7 个 ⚠️ 音色，逐个访问其角色官方规约页，检索关键词：
`再配布`、`音声素材`、`商用利用`、`事前連絡`、`無償配布`

输出：**可发布 / 需移除 / 待权利人确认** 三分类。

### 阶段 3：按审核结果决定发布内容

- 若通过审核的音色 ≥ 8 个 → 发布这些，其余不在发布包内
- 若通过 < 5 个 → 只发通过审核的，其余通过方案 B（用户自生成）提供

**核心原则（引用外部审阅意见）**：
> 宁愿第一版只带通过审核的声音，也不要为了凑齐 18 个音色承担不必要的发布风险。


### 关键约束（自我限定）

`licenses/AUDIO.md` 中**不得出现**以下表述：

- ❌ "本音频以 MIT 许可发布"
- ❌ "本音频为 CC0 / 公有领域"
- ❌ "已获 VOICEVOX 官方认可"

**只能**表述为：

- ✅ "本音频由 VOICEVOX 生成"
- ✅ "使用时须遵守 <角色> 的音源利用规约"
- ✅ "本插件不代表官方，也未获官方背书"

## 6. 待审阅者判断的关键问题

请重点复核以下五点：

### Q1：再分发的权利基础是否成立

ずんずん条款「他者に許諾する際は…義務付けてください」——
这是**对再分发的规范**（故允许），还是**仅对已获授权情形的补充**（故不构成授权）？

### Q2：`mochiko` 的判断是否需要更硬的证据

我方目前仅有二手信息称其"禁止无偿分发音频素材"。
是否需要我们直接抓取该角色规约原文并在此文档中引用？

### Q3：`AUDIO_MANIFEST.csv` 缺生成文本/参数，是否构成实质缺陷

无法复现生成是否影响"证明该文件确由 VOICEVOX 生成"？
有无其他可接受的替代证据（如文件格式特征、批量生成时间戳）？

### Q4：方案 A（下载）与方案 B（用户自生成）并存是否更稳妥

即：默认只提供**已审核音色**的下载，未审核的引导用户自行生成。
这样即使某个音色条款有争议，责任也落在"用户自己生成"一侧。

### Q5：免费 + 非商用是否应作为抗辩理由

我方立场：项目完全免费、无广告、无赞助、无商业化计划。
这在评估"是否超出许可范围"时应占多大权重？
