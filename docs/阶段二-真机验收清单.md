## 前置：重启 DSH（必须）

**为什么必须重启，不是 Ctrl+R**

插件的前端代码（`lib/client.js`）由宿主通过 `window.__ModuleLoader__`
注册进渲染进程。热重载只重载 Node 侧，**完全不触及前端**；
而 `Ctrl+R` 实测会被模块缓存挡住（2026-10-20 反复确认过）。

**判断是否真重启到位**：看日志里 `CLIENT-BOOT` 的版本号

```powershell
Get-Content "$env:TEMP\dsh-notify-say\notify.log" |
  Select-String 'CLIENT-BOOT' | Select-Object -Last 1
```

| 看到 | 含义 |
|---|---|
| `CLIENT-BOOT v0.4.76` | ❌ 前端还是旧代码，设置页不会有新开关 |
| `CLIENT-BOOT v0.4.84` | ✅ 这才是最新（**本次新增了版本号，之前是写死的**）|

> 注：`CLIENT-BOOT` 里的版本号目前是硬编码字符串，需要随版本更新。
> 本轮验收若发现它没跟上，我会改成从 package.json 读。

## D. Toast 精准跳转（本轮核心）

**需要两个会话同时可辨**，建议这样准备：

```
会话 A：在你常用的工作目录里开一个好的会话
会话 B：在别的目录开另一个会话
两个都发一句简单指令（如"回复 ok"），让它们先后完成
```

| # | 操作 | 期望 | 状态 |
|---|---|---|---|
| D1 | 保持 DSH 在**前台**，等一条完成通知 | 播报后**不自动跳转** | ⬜ |
| D2 | 点那条 Toast | **跳到对应会话**，且**不弹命令行窗口** | ⬜ |
| D3 | 切到别的窗口（后台），等一条通知，切回 DSH 时**不点 Toast** | **不跳转**（精准跳转已接管）| ⬜ |
| D4 | 后台期间产生通知，然后点 Toast | 唤窗 + 跳到该会话 | ⬜ |
| D5 | 两个会话先后完成 → 点 A 的 Toast | 跳 A | ⬜ |
| D6 | 同上 → 点 B 的 Toast | 跳 B（**不是最早那条**）| ⬜ |
| D7 | 快速连点两个 Toast | 最终停在**最后点的那个** | ⬜ |
| D8 | 关闭精准跳转开关后点 Toast | 只唤窗，不跳会话（退回旧行为）| ⬜ |

**日志对照**（每次点击都应看到这两行）

```powershell
Get-Content "$env:TEMP\dsh-notify-say\notify.log" -Tail 30 |
  Select-String 'jump-click|jump-consume|openSession'
```

```
[jump-click]   session=<A的id> from=http://127.0.0.1:<port>   ← 处理器写入
[jump-consume] session=<A的id> age=0s                          ← 前端读取
[ui] openSession CALL sid=<A的id>                             ← 执行跳转
```

三个 id 必须**完全一致**。若 `openSession THREW: unknown session`，
说明 id 对但有误（通常是测试用了假 id）。

## E. 协议生命周期（本轮新增，重点看）

| # | 操作 | 期望 | 状态 |
|---|---|---|---|
| E1 | 关闭精准跳转开关 | 注册表 `HKCU\Software\Classes\dshnotify` **被删除** | ⬜ |
| E2 | 重新打开 | 注册表**重新出现**，指向 `jump-handler.vbs` | ⬜ |
| E3 | 反复开关 3 次 | 每次都正确，无残留 | ⬜ |
| E4 | 手动建一个"别人的" `dshnotify` 键（指向别的 exe），再热重载 | **不被删除**，日志写「已被其他程序占用」| ⬜ |
| E5 | 手动把注册值改成一个**不存在的 vbs 路径**，再重启插件 | 自动清理并重新注册 | ⬜ |
| E6 | 检查 `%LOCALAPPDATA%\dsh-notify-say\port.txt` | 内容 = 当前 DSH 端口 | ⬜ |

E4/E5 的命令（可复制）：

```powershell
# E4：伪造"别人的"注册
$k = 'HKCU:\Software\Classes\dshnotify'
if (Test-Path $k) { Remove-Item $k -Recurse -Force }
New-Item -Path $k -Force | Out-Null
Set-ItemProperty -Path $k -Name '(default)' -Value 'URL:Other' -Force
$c = Join-Path $k 'shell\open\command'
New-Item -Path $c -Force | Out-Null
Set-ItemProperty -Path $c -Name '(default)' -Value '"C:\OtherApp\other.exe" "%1"' -Force
# 然后热重载插件 → 应保留 other.exe

# E5：伪造"失效的我们的注册"
Set-ItemProperty -Path $c -Name '(default)' `
  -Value '"C:\Windows\System32\wscript.exe" "<插件目录>\GONE.vbs" "%1"' -Force
# 然后热重载插件 → 应清理并重新注册为 jump-handler.vbs
```

## 已知限制（验收时请知悉，不算失败）

1. **点 Toast 后有最多 5 秒延迟**（探活兜底）。这是有意设计：
   前台点 Toast 时 `focus`/`mousedown` 都不触发，只能靠定时检查。
2. **首次点击多几十毫秒**（要拉起 wscript 进程）。
3. **安全软件可能拦截协议处理器** → 退化为只唤窗，不会更糟。
4. **前端改动必须重启 DSH**，`Ctrl+R` 无效。
5. **自动跳与点击跳互斥**：开了精准跳转后，两个自动跳开关不生效。
