## 二、发版工具（**别再造轮子**）

### `tools\release.ps1` —— 一键发版
升版本 → 测试 → 重建发布包 → 提交 → 推 GitHub →（可选）发 npm

```powershell
.\tools\release.ps1 -Bump patch              # 补丁版本，不发 npm
.\tools\release.ps1 -Bump patch -PublishNpm  # 同时发 npm
.\tools\release.ps1 -Bump none               # 只重建发布包+推 GitHub
.\tools\release.ps1 -Bump patch -DryRun      # 预演，不改任何东西
.\tools\release.ps1 -Bump patch -SkipTests   # 跳过测试（不建议）
```

**它已经解决的坑**（脚本里都有注释，不要重复踩）：
- 版本号只在提交说明里写、忘了改 package.json
- 发布包漏带 `tts-speak.ps1`（结果发布版没声音）
- 发布包漏带 `THIRD-PARTY-NOTICES.md`（合规问题）
- 重建发布包会清空 `.git`
- **npm 镜像问题**：本机 `.npmrc` 指向 `registry.npmmirror.com`（不能发布），
  脚本内部显式带 `--registry https://registry.npmjs.org/`
- **npm 发布"假成功"**：`npm publish` 返回 exit=0 且打印 `+ dsh-notify-say@x.y.z`，
  但 registry 上查不到（进异步队列）。脚本以 **`npm view` 可查**为唯一判据

### `tools\release-build.ps1` —— 派生发布包
自用版 → 发布版（减配：1 音色 2.82MB / 不外发内部文档 / private=false）

```powershell
.\tools\release-build.ps1                    # 默认派生到 `<发布包目录>`
.\tools\release-build.ps1 -KeepAllVoices     # 保留全部音色（测完整性用）
```

**为什么不直接发自用目录**：自用 16 音色 47.93MB vs 发布 1 音色 2.82MB。

## 三、插件内部结构（改代码前看这里）

| 路径 | 作用 |
|---|---|
| `lib/index.js` | 宿主半侧主逻辑（~3362 行）：notify / 空闲门 / preview / route |
| `lib/client.js` | 设置页 GUI（客户端半侧，沙箱渲染进程）|
| `lib/config-store.js` | 配置读写（`$DSH_HOME/storages/dsh-notify-say/config.json`）|
| `lib/config-schema.js` | 配置 schema 与默认值 |
| `lib/config-route.js` | 配置 HTTP route |
| `lib/session-bridge.js` | 会话跳转桥（`ROUTE_PREFIX = '/api/dsh-notify-say'`）|
| `lib/http-guard.js` | 本地来源防护 |
| `dsh-notify.ps1` | 弹 Toast + 放音（Windows 侧）|
| `tts-speak.ps1` | Windows TTS 朗读 |
| `jump-handler.vbs` / `.ps1` | `dshnotify-say://jump` 协议处理 |
| `sounds/voice-lines/` | 语音包 wav |

### 关键 HTTP 端点（都在 `/api/dsh-notify-say` 前缀下）
| 端点 | 用途 | 注意 |
|---|---|---|
| `GET /config` | 读配置 | |
| `POST /config/set` | 写配置 | 必须 `Content-Type: application/json` + `Origin` 头 |
| `POST /preview?kind=done` | 试听 | **3 秒限流**；被限流时仍返回 `ok:true` 但不写日志（易误判）|
| `POST /reload` | 热重载 Node 半侧 | 必须带 JSON body，否则 403 `write-requires-json` |
| `POST /pending-jump` | Toast 跳转落点 | |

### 配置项速查
- `audioSource` ∈ `tts` / `bundled` / `system` / `custom` / `none`
- `voiceName`：16 个音色，常用 `zundamon-normal` / `zundamon-amama` / `kyushu-sora` / `shirakami-kotaro`
- `ttsVoice`：Microsoft Huihui Desktop / Kangkang / Yaoyao / Zira
- `ttsTexts.done`（扁平键 `ttsTextDone`）：自定义 TTS 文案
- `debounceSeconds` / `globalCooldownSeconds` / `idleGate` / `toastJumpSession`

### ① 试听不传音色（本次拍摄实拍发现）
```
现象：界面选「九州そら」，试听却放「満別花丸」
根因：试听走 baseNotifyArgs()，音色参数只在 notifyArgs() 里加
修法：bundled 试听分支按「kind 级覆盖 → 全局」取值传 -Voice/-Mode
验证：[preview] -Voice kyushu-sora pick=kyushu-sora.wav
```
### ② `spawnTts(ttsArgs, psKind)` → `spawnTts(ttsArgs, pk)`
```
psKind 在该作用域未定义 → 选「系统语音合成」点试听必然 500
验证：[tts] 已朗读…（Microsoft Huihui Desktop）+ play-ok
```
### ③ 回归测试 `test/preview.test.mjs` 的 P4b
断言试听必须传 `-Voice`/`-Mode`。**已验证能失败也能通过**（回退修复后报错，恢复后通过）。
