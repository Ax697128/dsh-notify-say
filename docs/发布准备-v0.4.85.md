## 四、npm 发布的两个已知坑（已写进脚本）

### 4.1 发布返回 202 不等于已生效

npm 11 起发布改为异步：PUT 返回 **202 Accepted**，CLI 打印成功、exit 0，
但 registry 要等 **60~90 秒**才查得到。

`release.ps1` 现在会**轮询 `npm view` 确认可查**才报成功（v0.4.82 加）。

### 4.2 必须显式指定 registry

本机 npm 默认 registry 是镜像站 `registry.npmmirror.com`，
**镜像站不接受发布**（报 ENEEDAUTH）。

脚本已固定 `--registry https://registry.npmjs.org/`。

## 七、回退方案

若发布后发现问题：

| 场景 | 做法 |
|---|---|
| npm 包有问题 | `npm deprecate dsh-notify-say@0.4.85 "原因"` 并尽快发 patch 版 |
| 公开仓库有问题 | `git revert` 对应提交后重发 |
| 本机插件坏了 | `tools/snapshot.ps1 -Restore`（v0.4.85 新增） |

**不要**用 `git checkout -- <file>` 回滚 —— 会冲掉同文件里其它未提交的正确改动（坑 #452）。
